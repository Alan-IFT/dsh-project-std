## 背景与决定

插件的主要职责是标准技能、机械检查与只读迁移诊断。当前守卫另有通用 Git 风险清单、shell 词法与启发式写入识别，造成 profile 全局误问、复杂解析维护以及 Auto 允许后仍强制人审。用户明确要求职责收缩：不以修更多命令形态代替好的职责边界。

备选：①继续补 shell/Git 解析（不选：重复通用风险判定且不能成为硬安全边界）；②完全删除所有项目执行前约束（不选：宿主未获知项目冻结路径，无法替项目表达明确人审要求）；③保留最小、显式接入的结构化路径检查（选用）。不新增依赖、授权存储、风险模型、Shell/Git 规则 DSL 或批准标记。

**目标**：DSH 负责其沙箱、审批路由与可选 Auto review；插件只对可信 profile 配置明确登记的项目、明确列出的路径，在 `write`／`edit` 结构化工具调用上返回 `ask.reason`。无额外要求就原样消费下游，不把本地“无规则”说成宿主批准。`std-check`、技能与现有提交钩子不改算法。

**不能推论**：DSH 有审批服务不代表每次调用都风险分类；Full access＋never 没有 Auto 通用审查，也无文件沙箱。删除旧启发式后，shell/Git/解释器/直接 Node 的项目路径保护不再由插件覆盖。路径检查也不是目标侧文件权限、真实路径隔离或 symlink 防护；不得宣称已等价迁移到宿主。

## 新配置契约（policyVersion: 2）

插件标准 bundle 保持稳定两个 id（主插件与技能），主插件默认 `enabled: false`、`policyVersion: 2`、`projects: []`；技能仍启用。不根据项目目录自动启用，不从仓库文件读取授权配置。

需要项目路径人审时，由用户／profile 维护方在正常配置通道显式接入：

```yaml
# 仅为目标配置示例，不是本轮已改 profile；同 id 覆盖须写全。
- id: dsh-project-std
  name: dsh-project-std
  config:
    enabled: true
    policyVersion: 2
    projects:
      - root: 'D:\Programs\example-project'
        protect: ['AGENTS.md', 'CONTEXT_MANIFEST.md', '.githooks']
```

- `enabled` 必须是布尔值；没有配置不挂监听。enabled=true 要显式版本2、非空 projects；每项 root 必须为当前平台完全限定路径（Windows 盘符后须有根分隔符，或完整 UNC server/share；拒绝仅 `\\foo`／`C:foo` 等依赖当前盘符的形态，POSIX 为 `/` 起绝对路径），protect 为非空相对路径数组，整段匹配。没有内置 AGENTS／状态文件／钩子／本插件路径。
- 不允许相对 root、空 root、当前目录回退、相对 protect 中的 `.`／`..`／空段／绝对路径；错误配置明确抛错、不能静默丢弃。顶层只允许 enabled/policyVersion/projects（旧 root/protect 只用于迁移错误检测），项目项只允许 root/protect；未知键也报错。复用同一纯配置校验器处理 apply 与 schema 的完整输入，不先用会剥未知键的 object transform 投影再校验；不能把拼错的规则键静默忽略。Windows 保原大小写、段尾点空格、长路径前缀与 ADS 的词法比较兼容，protect 先验证原形再规整，规整后须再验非空、非根／绝对、无空段／`.`／`..`；Windows 点空格或 ADS 裁切不能制造根匹配或绕过。完全限定的会话 cwd 同样验证，不用 path.isAbsolute 单独证明 Windows 路径已无环境依赖。
- 不接受重复或父子重叠 roots，避免一个会话匹配多个项目时歧义与策略漂移。无默认项目，无 agent 侧动态加项目接口。
- 只在会话 cwd 为绝对且位于已登记 root 时应用该项目路径规则。相对 file_path 按**会话 cwd**解析，不按 root／进程 cwd 猜；不相关项目原样下游。匹配项目但 write/edit 路径缺失、空白或类型错误时 ask；Windows 目标含盘符但非完全限定（如 `C:foo`）、单根分隔符或残缺 UNC 时 ask 说明解析依赖环境，不能用 path.resolve 隐藏读取进程盘符 cwd。普通相对目标可含 `..`，只按已确认会话 cwd 规整，再对 root/protect 判范围；真正越 root 不宣由本插件保护。配置了项目但该结构化调用缺少有效会话 cwd 时 ask 并说明无法确定项目范围。其它工具不为这种缺失询问。
- 与 protect 相等或在其子路径的结构化写/改要求询问；仅前缀相似或越 root 的目标不受本插件规则约束。read/glob/shell/Git 等不解析也不新增本地 ask；不会把被主模型／宿主拒绝的效果转交另工具重试。
- 本地仅 ask／弃权。先取得标准 `next()`；其 ask/deny/cancel 按 PreToolDecision 的 SDK 分支原样保留，不能按自造严重度把取消或终结变成 ask/allow。next 抛错向宿主传播，不再吞异常伪称可以问人。无本地 ask 时原样 next；只有下游 allow 才加入本地 ask。不读 effective approval、更不按 never 放行。

## 迁移与覆盖变化

**本轮为未发布的配置契约破坏性候选**，package 版本暂不用于分发，发布时必须另按版本策略评估；相同 0.1.0 不能识别能力，升级必须核准确 commit/文件身份及 policyVersion，不能按版本号自动换装。

**旧配置是破坏性变更**。旧 `root`／`protect` 出现在主配置顶层时必须报错指向升级指南，不能默默解释为新默认关闭。Config schema 将完整输入送到同一校验器，按旧字段的存在检测并拒绝，不用 object 投影裁掉旧键；enabled=true 且缺新项目清单也拒绝。schema 不可用时仍由 apply 校验。插件挂载错误不是工具的执行失败关闭：若宿主仍能运行工具，不得声称错误时保护仍在。

所以升级不得自动执行：保旧安装与配置，先由维护方核新限制、决定哪些人审路径要保留，准备新 profile 配置；在正常可审批环境验证新插件挂载／结构化检查／更严下游保留，然后才能切换。失败退回原精确包与原配置；版本相同不可用版本号认能力。不写共享 profile、不能借改配置继续此前被拒动作。

本仓自己的入口合同／钩子／发布人审要求是项目意图，不因删启发式取消；现在明确只会在显式结构化路径规则命中时被插件消费。`--no-verify`、hooksPath 修改、强推、标签、状态文件 shell 清空等不再机械拦截，仍须按生效规则与正常用户授权处理；缺强制执行点记未定。提交钩子仍查质量，但不能防跳钩子、强推或全部暂存内容违规。D-108 的发布合同与 D-137 尚未生效的取代提议原样保留，本轮不顺手批准或改 release。

## 清理与实施顺序

先冻结本轮实际 dirty 版本的 src/guard/index.ts、policy.ts、src/index.ts、policy/regress/hooks-path 三份测试、guard mutation 与 bundle，保存原字节／完整 SHA256／路径／长度；快照逐文件与源 hash 验证一致后，写退役清单逐文件及混合断言说明去向和职责退出理由，再允许改/删。第六候选已有快照只作历史，不替代本轮包含接线与全部混合测试的快照。独立方案审查通过后，替换旧 `policy.ts` 为最小显式路径校验，不保 shell/Git 词法、commitMessageProblem（只有测试引用，真实提交信息由现 hook 查）。保稳定包入口/id/skills/bin。

旧 policy/regress/hooksPath 的规则断言与 guard mutation 随旧职责退役：保存精确快照及退出清单，再删除已不适用文件，新的项目路径测试接替，不保两套并行实现。退役理由是经用户确认的职责变化，而不是旧测试失败就删以变绿。原所有非 guard 测试、检查器/migrate源码与发布 blob 不动。

独立实现／代码审查／QA 使用互不重叠写集。编译只输出本轮自有目录，只同步实际变化的包产物，不覆盖已验 migrate。更新接入说明、插件入口注释、bundle 默认、仓库操作边界与当前状态；历史审计不改写。首次源码候选阶段审批 disabled，未换工具或改名补跑已拒效果。用户随后通过正常入口启用 ask，才正常同步入口并运行新接口测试、完整非退役回归、变异和真实宿主隔离组合验证；原拒绝与失败记录保留。安装与发布仍须独立核准接入前提，不能据源码验收推定已安装。
