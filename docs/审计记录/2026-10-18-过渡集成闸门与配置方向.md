## 决策与范围

用户先确认以集成／发布边界替代对 Git 命令写法的拦截：本地 revert、cherry-pick、rebase、快进合并以及跳钩子仍可写入本地历史，不能声称被路径层阻止。用户随后批准过渡发布合同：旧 `release`／归档 `ai-dev-std` 只读供未迁项目取既有标签，不发新版；新插件从本仓受保护 `main` 经 PR、必需提交树检查后按包版本号发布。D-137 的整体取代仍待三个项目迁移确认；生效范围与批准登记只以[决策日志 D-108](../决策日志.md#effective-register)为准，本记录不重复授权。

- 仓内候选为 `.github/workflows/verify-commit-tree.yml`：PR／推送读取提交树，锁定依赖、测试、自检与本仓检查。工作树钩子仍有原盲区；不改 DSH 路径守卫，不添加 `--no-verify`／`-c core.hooksPath` 命令询问。
- **远端仍须验证**：推送候选分支，观察 GitHub workflow 对提交树运行且通过；由有权限的维护者给 `main` 配置需要 PR、必需检查 `Verify commit tree / verify`、禁止免检绕过，再用坏内容真实 PR 确认不能合并，修复后重新检查才可合并。单独核对标签目标属于已检查的 `main` 提交；远端配置和拒绝回执缺一不称已受控。旧渠道不再写入。本仓不会把工作流文件存在等同保护生效。
