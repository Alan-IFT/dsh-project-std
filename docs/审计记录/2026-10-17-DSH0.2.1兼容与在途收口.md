## 3. 根因：0.2.1 起宿主导入前强制校验 `engines.dsh`

源码证据（只读实际安装的 ASAR，提取件在 `.staging/dsh-021-support-20261017/host-evidence/`）：

- `@deepseek-ai/dsh-app-boot@0.2.1-rc.2` 的 `lib/index.js` 新增 `unmetRequirements()`／`evaluatePluginCompatibility()`：**声明了 `engines.dsh` 时只由它决定**，否则逐条核对 `@deepseek-ai/dsh*` 的 `peerDependencies`；版本比较用 `semver.satisfies(runtime, range, { includePrerelease: true })`。profile 在导入插件前调用它，不满足即跳过该 bundle（`skippedBundles` 上报）。0.2.0-rc.2 的同一文件只有 peer 检查、没有 `engines.dsh` 分支。
- `@deepseek-ai/dsh-plugin-manager@0.2.1-rc.2` 的 README 同时写明：安装入口也会先拒绝不满足的包（`incompatible-version`），补救只有显式精确版本豁免（`dsh plugin allow-version` / plugin manager），**升级宿主或插件都不会继承豁免**。
- 旧声明是精确值 `0.2.0-rc.2`，对运行时 `0.2.1-rc.2` 不满足，因此**整包被跳过**。本会话的旁证：会话技能目录里没有 `std-*`，`skill` 工具对 `std-01-project-management` 返回 unknown；本会话所在 profile 装入的正是 `3ae6da0`。这是“已安装≠已启用”，不是安装失败。
