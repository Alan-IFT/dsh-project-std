# AI 辅助大型项目开发规范及工作流

本仓库用于共同研究一套从项目启动、开发、交付到长期维护都可执行的 AI 辅助开发方法。

**适用范围约束（2026-09-02 确立）**：本规范的受支持宿主是 DeepSeek Harness（D-135，2026-10-04 起不再支持 Claude Code）。正文的写法仍按「换一种工具要不要改」判，所以规范正文只写**语义不变量**，不写任何具体工具的入口文件名、目录结构、配置格式或脚本。判定与检验机制见[跨工具通用性](docs/09-跨工具通用性.md)（D-020，已接受）：**一条要求说不出两种互不相同机制类型的落地方式，就不得进入正文（可在同一宿主内；跨工具一项因只有一个受支持宿主而记未定）。** 载体上的实现只作为[附录·载体实例](docs/附录-载体实例/README.md)与[模板](templates/README.md)存在，效力为零。

当前只构建理论、候选协议与 Markdown 模板，不编写业务代码；候选规则已可装成真实 Gate——`std-check`（TypeScript，随 DSH 插件 `dsh-project-std` 分发）可作提交门；执行层是该插件的守卫（`tools/std/README.md`「DSH 接法」；已在隔离 profile 与重启后的真实 DSH 会话里验证：装入、技能加载、守卫询问被 DSH 采纳，依据与剩余未验证项见[设计 §12.43](docs/重构设计-TS插件化.md)）。已有三个采用项目仍是内嵌 `.std/` 的旧接法，迁移方案由 `std-check migrate` 只读产出，本仓不替它们执行。**语料版本号只有一处**，在[项目状态](PROJECT_STATUS.md)的 `corpus_version`——本文与各章都不再各自声明版本。

> 决策效力：**当前哪些规则可阻断或授权，只查[生效登记表](docs/决策日志.md#effective-register)。** 本文不复制那张表的内容——**条数也不抄**，抄一次就多一处会过期的副本（08 §7）。2026-09-03 起[正文 117 条原则整套进入`试行`](docs/决策日志.md#effective-register)（D-057，2026-09-23 续期一期，到期日见登记表该行）：**正文文本自此有阻断与授权效力**，此前十四轮它们全无执行点。

## 核心判断

大型项目后期变慢，通常不是代码生成速度不足，而是交付链逐渐失真：事实来源混乱、上下文取并集、状态无法恢复、规则只存在于自然语言、完成声明没有绑定版本和环境的证据。

架构由多个独立来源归纳而来（来源基数与统计见[架构确定](docs/架构确定.md)）：**四个平面加一条交付线**。知识平面是资产、执行平面是工具、控制平面是纪律、责任平面是人；换 AI 编程工具换的只是执行平面。按部件的失败诊断表见[00 总览](docs/00-总览.md)。
