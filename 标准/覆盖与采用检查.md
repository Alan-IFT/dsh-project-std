# 大型项目长期维护：覆盖与采用检查

用途是找采用缺口，**不是认证表或"内容齐全所以项目合格"的证明**。本文路由标准与证据，不重复规定默认加载集。文章和推导边界见[资料索引](参考资料/README.md)。

## 如何裁剪并开始使用

新项目先承载意图、状态和入口；跨模块时补架构边界；出现生产、持久数据、敏感信息或外部副作用时补相应运行前提。存量项目先盘点现有事实及缺口，从一个关键旅程试用，不先把目录铺满。存量项目没有架构文档时，按 [02 §1.1](02-项目架构描述规范.md#reverse-mapping) 从被改动的模块反向测绘起步，不先补全历史。

采用者在既有项目记录里给每项标"适用 / 不适用及理由 / 待确认"，并记录负责人、补齐工作项和复核时机。对象不存在才是不适用；缺人、没数据或没测试是待确认。高风险控制可以先以有责任人的人工检查运行，不因缺自动化无限等待；声称自动拦截时必须验证其真实执行点。

示例提供[可走查的运行工件](示例项目-连锁零售中台/docs/operations/README.md)及[反馈跨任务生效演练](示例项目-连锁零售中台/反馈跨任务生效演练.md)。它们均不能代替采用项目自己的真实证据。

<a id="feedback-adoption"></a>

**采用记忆沉淀或反馈改进机制时**，从已有工作项选一条有原始证据的反馈，按演练走查“本次修正 → 候选审定 → 原工件变更 → 后续使用 → 验证/撤销”，在该工作项记录适用分支的三态和证据。未启用该机制可按既有裁剪规则记不适用；缺样本、缺检查器或未运行的分支记未定。归类、去重、误召回和撤销的[成对用例](示例项目-连锁零售中台/反馈跨任务生效演练.md#cases)用于验证现有 03 §10～§11，不新增通用晋升次数，也不把本演练列为所有项目一律必跑的第七项试点条件。

## 试点通过条件

采用是一次变更，同样要有完成判据，否则"我们在用这套标准"永远无法被证伪。以下六条是**试点结束时的走查项**，不是长期达标线；每条给通过/失败/未定，未定要写清缺什么。

1. **接手可行**：一名未参与试点的人或一次全新会话，只依赖仓库与可用运行环境，能找到目标、现状与下一步，不需要问原参与者。做不到即失败，不记未定——这一条不需要额外数据就能当场试。
2. **跨工具接续**：两个工具先后接手同一项工作，后者保留了前者已有的修改与已生效的决策，没有推翻或重做。缺第二个工具记未定。
3. **同一套权威**：两个工具读的是同一份规则与同一组项目检查命令，不各带一份。发现第二处权威即失败，处置是合并而不是同步。项目里不放标准的副本；若有人复制一份来改，即制造第二处权威，改动要向上游报告（[01 §8](01-项目管理标准.md#adoption)），修复发布后再随插件升级取得。
4. **完成声明可核**：试点期内的完成记录带得起[证据六字段](01-项目管理标准.md#session-protocol)，并写明未解决的限制。抽查任意一条，能重新执行其确认方法。
5. **第二个项目可复用**：把公共部分用于第二个项目，技术差异由项目配置表达，不需要改公共协议。只有一个项目时记未定，不记通过。
6. **状态可区分**：草案、已废止与当前有效的要求在仓库里能清楚分开，包括本标准自己被裁剪掉的部分。

可持续观察但**不设达标阈值**的量：接手耗时、完成记录的证据完整性、重复缺陷、文档与实现冲突数、维护协议自身的时间成本。第一次试点只建立基线；用没有基线的数字宣称改进，属 [01 §4.8](01-项目管理标准.md#delivery-metrics) 禁止的口径。

试点未通过不等于标准无效，也不等于必须全套采用——按[如何裁剪](#如何裁剪并开始使用)缩小范围重试，并记下这次退出的原因与下次的触发条件。

## 尚未完成的验证与专题边界

- 尚未在真实大型项目验证维护收益、流程成本、SLO、恢复能力或安全效果；两轮资料驱动只完成了候选标准与工件补充。
- **[04 §7](04-可靠性安全与运行维护.md#model-capability-in-product)（产品内含模型能力）的证据基础明显薄**：一个项目的一份规范文本、零运行结果，加上本标准前身草案自己的一张清单；六条里只有两条绑定了已发生失败，且是同一个。该节覆盖的是运行责任，**产品级模型质量评估、提示词工程与用户侧质量口径未形成专题**。
- 语言/平台专属编码规范、详细测试实现、基础设施脚本、供应商 SLA 和特定法域合规不由这两轮材料穷尽；有对象时单独按官方资料核验。
- 财务预算、采购与许可证合规、隐私请求处理、可访问性、移动端/边缘离线升级及机器学习数据模型治理仅有一般责任入口；未形成独立专题，不能宣称本标准覆盖其全部要求。
- 宿主能力要按采用版本测试，研究卡不是持续更新的产品能力清单。发现收益不足或规则重复时合并/删减，不把继续增加文章当作唯一改进方式。

<a id="research-breakpoints"></a>

### 调研断点

**断点是活的义务，归口在本节。** 它原先挂在完善记录上；该记录已按 [01 §3.1](01-项目管理标准.md) 归档为一次性对齐工件（标准仓 `docs/审计记录/本轮完善记录.md`），归档区不承担更新义务，故断点入口移到这里。

- **未读的一手原文与未逐张看的图**：逐条见[资料索引·二次利用与断点](参考资料/README.md#二次利用与断点)。只拿到抓取工具返回的摘要时，该材料只用于核对与收紧，不用于新增条款；未读的图不采纳。
- **读取通道断点**（rsshub 主站被拦须走镜像、`openai.com` 单篇须用浏览器页内 fetch 取 SSR 正文、Anthropic news RSS 只回最近 10 条且不含 engineering 博客）见[资料索引·追加专项](参考资料/README.md#addendum-2026-09)。
- **未落地的跨方向建议台账**：两轮共登记约 60 条，只落地两条加若干指向性修正。多数经核对已被目标章节覆盖，再落一次会造成同一判据的第二处文本、按 N2 判缺陷；少数归属存疑或证据不足。台账不随交付，后续按真实缺口取用，条数清空不是目标。

### 下一次真实项目验证的启动条件

由采用项目在自己的授权会话选一个**确实在维护的关键旅程**和负责人；本仓只提供判据、工具与交接说明，不代访问采用仓或修改其业务政策。试点前由项目自身保存同一口径的基线：完成记录及接手用时、反复维护劳动与运行成本、适用的 SLI/SLO、恢复演练与安全检查原始回执；没有生产对象的项目只测适用项，明确不适用与未定。提前确定观察窗口、样本、版本／环境、投入量和停止／撤回条件；试点期对照[试点通过条件](#pilot-exit)逐项走查，并记录规则额外成本与误阻断，不把通过项数或缺失数据当收益。前后比较控制项目和测量口径变化，缺基线或无法区分同期干预时结果记未定，不宣传因果改善。

优先在**已上线且由项目方自愿提供证据的模型能力**上试 [04 §7](04-可靠性安全与运行维护.md#model-capability-in-product) 的版本回读、调用出口、失败形态及供应商变更发现；无此能力不虚造实例。财务／采购／许可、隐私、可访问性和离线升级等专题，只在相应真实对象出现且现有职责卡回答不了一个可定位问题时另立专题并核一手依据；跨方向建议依真实缺口提取，不以清单清零作结束条件。
